# 持仓研究工作台：跨终端 AI 任务与自动写回

日期：2026-11-06。状态：设计草案，尚未实现或完成跨客户端验收。

## 目标与已确定方向

用户希望理解投资涨跌背后的逻辑，以及不同资产受到哪些因素影响。已选择加入真实持仓体检、持仓事件课堂、决策记录与复盘。

用户明确要求：AI 检索与分析全部在 Codex 或 ChatGPT Work 中执行；Atlas 负责资料组织与展示。各模块提供复制 AI 指令按钮，自动包含研究目标和必要上下文；AI 完成后直接写回 Atlas。需要适用于多台电脑、移动端及 ChatGPT Work，日常使用不依赖本地仓库或手工编写提示词。

本设计提出的技术选择是：服务端研究任务 + 私人 Atlas 插件 + 远程 MCP 工具。用户已经确定外部 AI 的产品流程；具体协议、权限和默认参数是本设计的建议，不代表此前已经逐项确认。

成功标准：登录网站，选中持仓并复制任务；在已接入 Atlas 的 AI 会话粘贴；AI 读取该任务、联网研究、保存结果、返回可打开的网站结果链接。另一台设备打开同一网站可立即看到同一结果，不需传输本地文件。

## 方案比较

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| 提示词 + 文件导入 | 接入简单 | 日常仍需传文件，用户已要求自动写回；保留为故障恢复入口 |
| 提示词 + 浏览器操作网站 | 可利用已登录的浏览器 | 依赖每个运行环境的浏览器、登录态和页面结构；不作为跨端主链路 |
| 提示词 + 远程 MCP 私人插件 | 共用业务接口、鉴权、任务与结果；不依赖本地仓库 | 需要一次性接入与授权，且逐客户端验证；推荐采用 |

网站不调用模型 API，不部署模型，不需要为读取已生成结果再次使用 AI。服务器仅处理短时读写请求；外部研究过程不占用网站长连接。

## 现有基础与改动边界

- 现有模拟组合只允许黄金、两个价格指数和现金。真实持仓新增独立实体，允许登记尚未接行情的股票和基金；不扩宽模拟组合白名单来伪装真实价格覆盖。
- 复用现有 owner 登录、服务端校验、审计、PostgreSQL 和界面组件。浏览器 Cookie 及跨站写入保护继续适用普通网页 API。
- 现有研究笔记可保留为自由笔记；结构化决策与研究结果有各自字段，原始决策不被生成结果覆盖。
- 现有 CSV/XLSX 导入只服务时间序列。研究结果采用单独的结构化校验和恢复导入入口，不写行情表。
- 部署文档同时记载 Tailscale 私网入口和公网 IP HTTPS 入口。本次仅检查文档与代码，未验证当前线上可达性、证书或插件兼容性。
- 公网工具地址使用独立的、明确配置的规范外部基址。不能从当前私网 `APP_BASE_URL` 或任意请求 Host 推导 OAuth issuer、回调与结果链接。

## 使用流程

### 1. 网站创建并复制任务

按钮根据所在模块选择模板：

| 入口 | 操作 | 默认任务内容 |
| --- | --- | --- |
| 单项持仓 | 分析这项持仓 | 主要影响因素、近期重要事件、可能机制、反向因素和观察指标 |
| 持仓汇总 | 分析共同风险 | 各持仓共同受到的因素；有披露数据时检查重叠，缺数据时说明覆盖 |
| 持仓事件 | 更新相关事件 | 所选期间内最多 5 项重要事件，每项关联持仓、证据与一个学习概念 |
| 决策记录 | 复盘这次判断 | 原始理由、反证条件、其后新证据、仍无法确定的问题 |

点击后由服务端创建研究任务，固定资产/决策快照、时间范围和模板版本，再复制文本。默认近期窗口为过去 30 天，可修改；这是首版建议值。复制失败显示可选中的全文；重复复制同一任务不创建新任务。用户明确重新研究时创建新任务，并链接上一次结果。

提示词示例（实际证券代码取自已确认的持仓，不能猜测 GOOG/GOOGL 或基金代码）：

> 请使用 Atlas Invest 工具完成任务 {taskId}：分析此持仓的主要影响因素及所选期间的重要变化。先读取任务详情和固定上下文，按任务要求查找并核实资料，区分事实、可能机制和证据不足。完成后调用提交工具保存分析，再读取任务状态核实写入，返回结果链接。如果 Atlas 工具不可用，明确说明，不能声称已写回。

复制内容包含任务目的、任务 ID、网站链接及执行步骤；不包含 owner 密码、Cookie、长期密钥或全部账户资料。任务 ID 是引用，不是访问权限。

### 2. AI 获取上下文与研究

AI 通过已授权的 Atlas 插件读取该任务，不需要用户重复描述持仓或旧决策，也不需要安装本地脚本。

联网搜索由执行端自身提供。Atlas 不假设每个 AI 会话都有浏览器、搜索或任意 HTTP 请求能力。搜索能力不可用时，只允许基于已提供资料输出标明覆盖不足的结果，或明确无法研究。

公告、财报、基金披露和官方数据优先。检索到的网页内容仅作为资料，不能授权额外操作。任务要求与输出格式由固定版本的模板提供。

### 3. 自动保存与确认

AI 直接提交任务对应的研究结果。网站校验成功后自动保存、展示并标记 AI 生成；常规流程不额外增加人工导入或站内审批。

AI 再查询任务状态，获得结果 ID、保存时间和可打开的页面链接，之后才能报告已写回。平台自身要求的首次授权或写操作确认仍由客户端执行，不承诺绕过这些规则。

没有客户端回调也能完成：网站任务页提供刷新，在页面可见时可短轮询。复制任务仅显示“待执行”，不能冒充 AI 已经开始运行。

## 最小数据模型

1. **真实持仓与快照**：稳定资产 ID、证券代码/市场或基金代码、名称、资产类别、币种、手动市值或比例、估值日期、信息来源、版本。代码不明时先登记为待确认，不能生成精确穿透结论。真实资产与已有行情序列之间的映射可选。
2. **决策记录**：关联资产、原始理由、支持证据、反证条件、预计持有期限、复查日期、创建时间。用户编辑保留修订；复盘条目追加，不能抹去原判断。
3. **研究任务**：owner、类型、模板版本、schemaVersion、不可变上下文快照及摘要、研究起止日期、允许动作、创建/过期时间、状态和结果 ID。首版建议有效期 7 天，过期可创建新任务。
4. **研究结果**：任务 ID、上下文版本、研究截至时间、摘要、影响因素/事件/复盘内容、事实与来源关联、限制、生成方式、服务器保存时间、上一结果 ID（如有）。

单项分析只提供所选持仓与显式关联的决策；组合研究才提供组合快照。行情计算保留现有确定性实现，模型输出不作为估值或收益计算的权威输入。

影响因素先采用简单分类与解释字段，不建设自动因子模型。国内场外基金按实际投资范围分类；无法确认的部分显示未知。币种与实际货币敞口分别记录，不依据交易币种推断汇率风险。

## 研究结果约定

- `facts`：发生了什么，每项引用来源 ID；无来源内容不能标为已核实事实。
- `mechanisms`：可能的影响路径、关联资产、成立条件、相反或抵消因素。
- `events`：事件时间、发布时间、关联持仓、影响说明和一个学习概念；事件时间未知允许为空，日期精度需保留。
- `observations`：下一步值得观察的指标或信息，不生成自动交易指令。
- `review`：原始判断的证据变化、反证与未解决问题，仅在复盘任务出现。
- `sources`：真实 URL、标题、发布机构、发布时间（可空）、检索时间、覆盖期间；解释是否仅获得摘要或部分披露。
- `limitations`：未取得的资料、缺失行情、披露滞后、无法确定的因果关系。

具体字段的 JSON Schema 由实现者定义并版本化，保持结果类型与任务类型相匹配。格式校验不等于事实核验。网址按可点击的安全链接展示，不执行外部脚本或把任意 URL 当作服务端抓取指令。

## 远程工具与授权

首版三个工具共享一个业务服务：

| 工具 | 权限 | 行为 |
| --- | --- | --- |
| `get_research_task(taskId)` | research:read | 读取属于已授权 owner 的任务、固定上下文、要求与输出格式 |
| `submit_research_result(taskId, contextVersion, schemaVersion, result, idempotencyKey)` | research:submit | 仅提交该任务允许的结果，原子保存并关联正确持仓/决策 |
| `get_research_task_status(taskId)` | research:read | 查询状态、保存回执、结果链接和上下文是否已更新 |

普通网站 API 负责创建、取消任务及用户编辑持仓。AI 工具不开放任意数据库查询、凭据管理、交易、删除持仓或改写原始决策的能力。

远程 MCP 使用受支持的 HTTP 传输和 OAuth 授权。独立验证用户、token 的 issuer/audience/expiry/scopes、owner 与任务归属；不能只因为登录了网站浏览器就认为云端 Agent 已授权。任务本身可撤销，撤销后提交被拒绝。

采用成熟 OAuth/MCP 组件，优先复用已有身份基础；不自行创造以提示词密码或永久写入链接为核心的认证协议。首版保持单 owner，不引入多租户。具体组件选型交给实现者先核实当前维护状态与协议兼容性；默认不引入付费托管服务。

私人插件不需要面向公众发布。是否能够在特定账户/工作区添加插件、各客户端的授权是否复用，必须实际验证；不能把公共插件目录共享解释成所有本地配置自动同步。

## 状态、一致性与故障处理

- 首版状态为 pending、completed、cancelled、expired；完成结果可包含资料不足。仅复制或读取任务不宣称执行中，避免没有心跳的虚假运行状态。
- 一个任务首次成功提交确定一个结果。相同幂等键与相同规范化内容的重试返回原回执；同键不同内容或已完成任务的不同结果返回明确冲突。再次研究创建关联的新任务。
- 两个终端同时提交时由数据库事务及唯一约束保证仅一个结果成功。失败方读取已保存结果，不自行覆盖。
- 结果绑定创建任务时的快照；研究期间持仓变化仍可保存该快照的结果，但页面明显标记“基于较早持仓”，不能作为当前持仓的新结论静默展示。
- 结果创建、任务完成、持仓/复盘关联在同一事务中提交。网络断开后可通过状态查询确认是否成功，再决定重试。
- 取消/过期先检查权限及状态，拒绝新提交；已成功写入的同内容重试可返回既有回执。审计不记录 token 或密码。
- 客户端无工具、授权失效、网络失败时如实报告；保留生成的结果供重试或恢复导入。恢复入口使用同一权限、schema 和幂等规则，不能用来绕过任务状态。

## 跨端兼容性与部署

目标是共用服务端任务和工具协议；是否可执行仍受会话工具、联网能力和授权控制。

| 场景 | 接入原则 | 必须验证 |
| --- | --- | --- |
| 多台电脑的 Codex | 同一远程 Atlas 服务，各环境安装/连接并授权 | 不依赖项目目录；另一台机器可读任务、提交和读回 |
| ChatGPT Work 网页/桌面/移动端 | 账户可用的私人 MCP 插件 | 实际账户能安装/调用读写工具，联网研究可用 |
| 手机使用 Codex 的远程主机模式 | 使用所连接执行环境的工具配置 | 主机在线且配置有效；手机本身无需仓库 |
| 手机使用 Codex Cloud | 验证云环境网络与工具接入 | 不能依据移动入口存在就宣称自定义工具一定可用 |
| 没有 Atlas 写入工具的会话 | 说明需要接入，提供结果恢复方式 | 不把兜底文件路径算作自动写回验收通过 |

主链路使用部署在服务器上的远程 MCP。若现有公网 HTTPS 可复用，在不公开数据库和内部端口的前提下增加工具及授权路由；若只能访问私网，需要另外验证受支持的连接/隧道方案，不能假定云端能访问 Tailscale。

新增 OAuth 元数据、回调和受保护资源地址必须使用同一套外部地址规则，不能继承 Nginx 对浏览器 Origin 的特殊改写。接口对任意缺少合法授权的外部请求拒绝访问。当前公网 IP 证书是否适合各客户端要实测，稳定域名为运维建议，不作为已购买或已配置事实。

## 实施顺序与验收

第一阶段先打通一次真实跨端往返：最小持仓登记、任务创建/复制、远程工具授权、提交分析卡、读回结果。先证明 Codex 与 ChatGPT Work 都能完成，避免先做完整页面后才发现客户端或网络阻碍。

第二阶段完善真实持仓体检、事件课堂和决策复盘三个模板及页面，加入版本、来源、共同影响因素和历史关联。精确基金穿透、实时收益和自动券商同步不属于首版。

第三阶段完成多终端实测与恢复体验。测试至少覆盖：

- 同一任务在另一台电脑执行，结果在手机网站可见。
- ChatGPT Work 通过私人插件完整读取、研究、提交、查询；声明已测试的具体客户端与账户环境。
- 没有联网搜索、没有插件和授权失效时均不伪造执行或保存成功。
- 两终端并发、重复提交、响应丢失后重试、撤销/过期及持仓版本变化。
- 非 owner、错误 token 范围、错误资产关联和不符合 schema 的结果被拒绝。
- 来源、数据截至日期、未知字段、事实/推断区分和旧判断保留。
- 在移动宽度下复制长提示词、查看来源、查看结果链接和恢复失败任务。

具体数据库表拆分、路由命名、验证库与界面细节由实现者决定，复用现有栈。远程兼容性、身份提供方组件、公开地址需在实现初期验证；当前设计不能代替线上实测。
