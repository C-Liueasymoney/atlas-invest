# Asset Correlation & Portfolio Risk Implementation Plan

Goal: extend existing catalog/query/provider/widget system with return correlation, rolling analysis and persisted hypothetical portfolios.
User explicitly requests direct implementation and three separately verified/pushed phases.

- Phase1: pure calculations; asset semantics registry (price vs basis-point changes); exact interval/date alignment with no carry-forward; daily/ISO week/month resampling; FX exact-date conversion before returns; versioned bounded cache; availability, correlation, rolling and refresh internal APIs. Use database first, existing persisted index provider history only if database unavailable, no quote-as-history. Test numerical edge cases and alignment, run lint/typecheck/test/build, commit/push.
- Phase2: /analytics/correlation, searchable catalog, dates/frequency/base, matrix/rolling/detail CSV, existing ChartCanvas with bounded axis or native SVG if necessary; register correlation and rolling widgets, integrate layout config validation and navigation. Validate browser/widget save, commit/push.
- Phase3: saved portfolios CRUD/copy/rename, percent/amount mode, cash/exposure semantics, multiplicative FX scenario and thresholds, stress widget, complete-case history risk endpoint interface. No invented ETF data. Tests, README/source inventory, final review and commit/push.

Ruling: use existing branch codex/atlas-v1 and stage explicit files to preserve dirty workspace repairs; no external dependencies. History risk is stage-two enhancement, API should explicitly return unavailable if not implemented. Pricing indexes are price-return series (no dividend total return). Same-date cross-market closes can be asynchronous; warn. Analysis requires at least 20 paired observations; macro inputs labelled changes and excluded from portfolio positions.

API contract Phase1: GET /api/v1/analytics/assets/availability -> {items: AssetAvailability[]}; GET correlation?assets=IDs&from=YYYY-MM-DD&to=...&frequency=daily|weekly|monthly&currency=CNY|USD -> {assets:AssetAvailability[],matrix:Cell[][],frequency,currency,from,to,isDemo,algorithm,warnings:string[]}. AssetAvailability={id,name,currency,unit,transform:'return'|'bp-change'|'unsupported',status,source:{id,label,url},asOf,fetchedAt,count,reason?}. Cell={a,b,value:number|null,n,from:string|null,to:string|null,reason:string|null,missingRate:number}. GET correlation/rolling same query + a,b,window=30|60|120|252 -> {points:{time,value:number|null}[],pairs:{time,x,y}[],cell:Cell,window,warnings,isDemo}. POST analytics/refresh {assets:string[]} uses existing sync adapter (no direct frontend third-party requests).
